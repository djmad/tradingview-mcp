# IHSG screener provenance and operating contract

Adapted from [upstream PR 511](https://github.com/tradesdontlie/tradingview-mcp/pull/511), source commit `3768597ed07f4925c0574b9faf4cd95a2efd59eb`, authored by ioxis99. The PR was published 2026-09-06. That publication date is not a proven universe-membership date: the CSV has individual listing dates but declares no membership as-of date. Results therefore expose `universe.as_of: null`, `source_pr_published_on`, source revision, content revision, and `current_membership_verified: false`.

The source snapshot contains 951 unique symbols, qualified as `IDX:TICKER`. It is not advertised as today's complete index membership. The 12 pure pivot/Fibonacci/price-pattern/volume detectors and reference-level calculations are source heuristics. Their comments and historical backtest rationale are attribution, not independently measured performance in this fork. No order execution or brokerage connection is included.

`IHSG_Screen` is a write-classified MCP tool because it temporarily switches its session-selected chart and can create local report files. It does not launch or close TradingView, schedule a daily task, or run an automatic full scan on import. It uses existing target ownership, CDP deadlines, and an exact logical-scale viewport helper. Source helper scripts that auto-launch, spawn child scans or run scheduled jobs were deliberately not imported.

Each call scans at most 10 symbols (default 5) in daily timeframe with a bounded work budget. Supply the returned `page.next_cursor` with the same symbols, criteria and liquidity threshold to continue; the cursor binds the offset to those inputs. `page.done` means all selected snapshot symbols have been processed across those calls. Errors remain explicit and may require retrying failed symbols separately. A scan or restoration with an uncertain outcome is not blindly repeated. External chart/layout/viewport changes stop further writes and prevent restoration over the user's newer state.

Reports under `.local/ihsg/` cover one batch only; they do not claim to aggregate prior pages. JSON contains outcomes, errors, data timestamps, configuration and restoration receipt. Markdown and XLSX carry batch/provenance and daily-bar freshness limits. XLSX cells use literal strings, not formulas. Files use unique exclusive names; callers cannot provide arbitrary output paths.

Defaults: `limit=5`, `timeout_ms=30000` (maximum 45000), minimum 50-day average transaction value `1e9` Rupiah, all 12 criteria, reports enabled. Cleanup has a separately bounded 5-second budget. The latest loaded daily bar may still be incomplete; every analyzed outcome records its actual timestamp and bar count. Fewer than 60 daily bars are skipped explicitly. The scanner does not silently load years of history or substitute another instrument's bars.

Verification: synthetic detector/liquidity/shape/cursor tests, actual-adapter VM guards for layout/viewport races and expired operations, restoration contract tests including future whitespace, and exclusive JSON/Markdown/XLSX roundtrip tests. The actual current chart's symbol-info/loading/viewport/bar-reading APIs were also probed read-only without changing symbol or timeframe. Full live IDX scanning and historical profitability were not validated by this agent. Root integration performs any separately authorized small live smoke test.

Native delayed-feed normalization: requested IDX:BBCA was observed as full_name IDX_DLY:BBCA while both chart and main-series pro_name remained IDX:BBCA, exchange/source_id were IDX, and both delay fields were 600 seconds. Only this qualified canonical IDX/IDX_DLY relationship with matching explicit metadata is accepted; a same bare ticker on another exchange or old main series never passes. D and 1D are equivalent daily resolution spellings. Outcomes record requested_symbol, actual_symbol, actual_resolution and delay_seconds; report tables expose feed/delay. This is feed metadata, not a promise of real-time data.

Structural protection: scanners capture chart type and complete observable study/drawing ID lists, check them atomically before setters, and require them in final restoration proof. An unnamed, unidentifiable or unready existing study refuses the scan before any write. An earlier live smoke found an unnamed component missing after a symbol change; its departed source was no longer resolvable, so its identity/cause cannot be reconstructed or certified as a disposable replay overlay. It was not recreated blindly. No code path removes a study or drawing.
